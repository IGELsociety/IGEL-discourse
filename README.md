# Concordance forum: static archive

Read-only mirror of the IGEL **Concordance** forum (`discourse.igelsociety.org`, Discourse 2.8.0.beta11),
built to replace the live forum at the same domain and the same URLs. See `discourse-archive-plan.md` for the plan.

- **Snapshot:** 2026-10-01 (every page says so).
- **Content:** 271 topics in 21 categories (11 top-level, 10 sub), 548 posts of which 509 are rendered (the other 39
  are empty "pinned/closed" system events), 458 asset files (images, emoji, PDFs, Word files), full-text search over
  293 pages, 1,461 redirect rules.
- **Only what anonymous visitors could see.** The forum itself reported 280 topics and 1,498 posts; the rest is not
  public and exists only in the Phase 0 backup (`concordance-*.tar.gz`, never committed).

## Layout

| Path | What | Committed |
|---|---|---|
| `raw/` | Redacted copy of the harvest: the regeneration source of the site. `manifest.json` has the snapshot date and hashes. | yes |
| `raw_verbatim/` | Byte-exact harvest, **unredacted** (e-mail addresses, Zoom passcodes, avatars). Local only. | **never** |
| `dist/` | The built site (pages, assets, `pagefind/` index, `_redirects`, `sitemap.xml`, `robots.txt`): what Cloudflare Pages serves. Generated by `make all`; commit it after every rebuild. | yes |
| `R/01_harvest.R` | Phase 1: read-only crawl of the live forum into `raw_verbatim/` (the only step that needs the network). | yes |
| `R/01b_redact.R` | `raw_verbatim/` to `raw/`: removes personal data, except the addresses of `redaction-allowlist.json`. | yes |
| `redaction-allowlist.json` | The organisation e-mail addresses that stay (each with its reason). | yes |
| `R/02_build.R`, `templates/` | Phase 2: `raw/` to `dist/` (whisker templates, one stylesheet). | yes |
| `R/02b_redirects.R` | Phase 4: writes `dist/_redirects` so the old forum URLs keep working. | yes |
| `R/03_audit.R` | Phase 5: the final gate; writes `audit-report.json` and exits 1 if a check fails. | yes |
| `renv.lock`, `Makefile`, `backup.sha256` | pinned R packages; the pipeline; SHA-256 of the Phase 0 backup. | yes |

## Rebuild

Needs R 4.4 (packages are pinned by renv: `renv::restore()`), and Node with `npx` for the search index
(`pagefind@1.5.2`, downloaded on first use). Everything except `make harvest` works offline.

```
make harvest    # network: refresh raw_verbatim/ (add --force to R/01_harvest.R to re-download everything)
make redact     # raw_verbatim/ -> raw/
make all        # build + search + redirects + audit  (raw/ -> dist/, ends with the audit table)
```

A build replaces `dist/` entirely, so always run `make all` (not `make build` alone): the search index and the
redirects are generated after the build. `make all` works from a fresh clone, because `raw/` is committed.

## Home page

`templates/home.html` has the Pagefind search box under the title. `home_data()` in `R/02_build.R` lists the IGEL
conference categories first (any top-level slug `igelYYYY`: `igel2025`, `igel2024` ...), newest year first, and
the other categories after them in the forum's own order. The home page and `/search/` are the only pages with a
`<script>` (the search widget): the build's self-check and audit check 9 reject a script anywhere else.

## Privacy decisions

- **Redacted in `raw/`:** e-mail addresses and mailto links (27 found, 25 redacted), Zoom passcodes in links, in plain
  text and as the lower-cased copies Discourse put into heading anchors (116 in all), one obfuscated address.
  Names and usernames are kept, as on the live forum.
- **Kept on purpose (`redaction-allowlist.json`):** two general addresses of support organisations, the helplines of
  Dublin Rape Crisis Centre and One in Four in the support list of topic 756. To keep another address, add it to
  that file with a reason and run `make redact all`; the audit checks that each listed address is on the site exactly
  as often as the redaction report says, and still fails on every other address.
- **Left out:** user pages (mentions are plain text), avatar images, the 39 empty system-event posts.
- **Published as uploaded:** the 33 PDFs and 7 Word files. 22 of the PDFs contain an e-mail address of their authors
  (found by the audit, a lower bound); they are the authors' own posters and abstracts, so this was accepted.
- **Kept on purpose:** the OSF view-only and Dropbox share links (3 on the pages): they only work with their key.
- **Erasure requests:** edit or delete the content in `raw/` (a post in `raw/topic/{id}.json`, a file in `raw/assets/`),
  then `make all`. Do not run `make redact` afterwards unless `raw_verbatim/` was edited the same way, because it
  regenerates `raw/`.

## Checking a build

`make audit` prints a table of 11 checks and must end with `AUDIT PASSED`. It re-derives everything from `raw/`
and `dist/` independently of the build: every topic and post present, no word of any post lost, no link or asset
missing, no forum host or personal data in the output, the search index and the redirects consistent.
With `raw_verbatim/` present it also searches the output for the original sensitive values.
Manual steps it cannot do: compare topics with the live forum side by side, and read each redacted passage in
its context (the audit lists them).

## Deploying (Phase 6, by hand)

1. **Before anything else:** two copies of the backup in different places, verified with `backup.sha256`.
   Revoke the Discourse API key that was created for this project (the harvest was anonymous and never used it)
   and make sure no copy of it is left in the folder or the repository.
   Decide what happens to the non-public part of the forum (see top): it is only in the backup.
2. **Getting `dist/` onto Cloudflare Pages** (free plan: unlimited static requests, 20,000 files and 25 MiB per
   file allowed; `dist/` has 1,087 files, the largest 3.7 MB). Pages' build image has no R, so it cannot run
   `make all`: it deploys the prebuilt `dist/`, which is therefore **committed** to this repository (the host is
   Cloudflare rather than GitHub Pages because GitHub Pages ignores `_redirects`, which keeps the old URLs working).
   In the Cloudflare dashboard create a Pages project from `https://github.com/IGELsociety/IGEL-discourse` (the
   Cloudflare GitHub app must be allowed for the organisation), production branch `main`, framework none,
   **empty build command**, build output directory `dist`.
   After any rebuild run `make all`, commit the changed `dist/` and push; Pages redeploys on its own.
   (Alternative without Git: `npx wrangler pages deploy dist`, which needs Node 22 or newer; the dashboard's
   drag-and-drop upload is limited to 1,000 files and cannot take `dist/`.)
3. **Test on the `*.pages.dev` address first** (the redirects cannot be tested offline). With `<host>` the preview address:
   - `/t/does-reading-about-fictional-minds-make-us-more-curious-about-real-ones/365` (no slash): one redirect to the same URL with a slash, then the page.
   - the slash form `/t/does-reading-about-fictional-minds-make-us-more-curious-about-real-ones/365/` opens directly, with no redirect loop.
   - `/t/365`, and `/t/can-literary-refugee-narratives-decrease-ingroup-bias-an-experimental-reader-response-study-using-implicit-methods/197/5` (lands on post 5).
   - `/c/igel2023`, `/c/announcements/events/7`, `/latest`, `/u/anyone` (all to a real page), `/nope` (the 404 page).
   - `/search/`: search "empathy" and use the Tag filter; open a result.
   - a PDF (`/uploads/short-url/tUHMhFQ1djydvAV9oV8pQXyOPzA.pdf`) and an image in a topic.
   If the no-slash URLs loop, Pages treats `/x` and `/x/` as the same source; remove the 293 rules that only add a
   slash and redeploy (everything else stays valid):
   `awk '{ if ($0 ~ /^#/ || NF < 3) print; else { d = $2; sub(/#.*/, "", d); if (d != $1 "/") print } }' dist/_redirects > _r && mv _r dist/_redirects`
4. Announce to members, with a date, that the forum becomes read-only.
5. **DNS cutover.** First add `discourse.igelsociety.org` as a custom domain of the Pages project in the dashboard,
   only then replace the domain's A record by a CNAME to `<project>.pages.dev` (doing it the other way round gives
   a 522 error). Check the site on the real domain.
6. Keep the droplet powered off, not destroyed, for a week. Then verify the backup against `backup.sha256`, and destroy it.
7. Update the society's privacy page: the forum is archived and frozen, attachments are published as uploaded,
   and erasure requests are handled manually (see above).

If the forum is still being used when you cut over, take a fresh backup and refresh the harvest first
(`Rscript R/01_harvest.R --force`, then `make redact all`).

## Known limits

- Links to topics that were never public, to `/tags`, and to one removed system post are plain text.
- Old URLs with an outdated topic slug redirect only if the slug was seen inside the archive (3 cases); other
  outdated slugs, `.json` and `.rss` URLs, and trailing-slash spellings such as `/latest/` give the 404 page.
- 797 external links (363 to doi.org), 147 YouTube videos and 4 hot-linked thumbnails depend on third parties and will rot.
- Search results are only as good as Pagefind's partial-word matching; it uses the "Default UI", which is supported.
